開示 (このタスクでは修正していない)

上の走査では effect ごとに挙動が割れた。
· :recommendation/mark-finalized は cases + recommendations に承認者を残さない (S3, 承認者 adj-hanako)。
· :case/upsert は cases に承認者を残さない (S10, 承認者 tpa-tanaka)。
原因は auxiliary.operation/commit-record が承認者を :payload にだけ載せるのに対し、auxiliary.store/MemStore の :case/upsert は :value を使い、:recommendation/mark-finalized は :value も :payload も使わず finalize! を呼ぶため。:assessment/set だけが :payload を使うので承認者が残る。

台帳側も同じ穴がある: 実行された :approval-granted fact は run の :audit チャネルには載るが、commit ノードが台帳へ書くのは commit-fact だけなので、永続化された台帳 11 件のうち :approval-granted は 0 件、承認者らしきキーは 0 件。つまり「誰が承認したか」は永続層に残っていない。

rendering タスクの範囲で governor / store を書き換えるのは筋が悪いので修正はしていない。ここに開示する。

:actor は承認者ではない。 台帳 fact の :actor は :context の実行主体 id で、実測値は op-1。この run で使った承認者 id は adj-hanako tpa-tanaka であり、両者は交わらない (互いに素であることを実測) — :actor を承認者として読むと、この 2 つが同じ値の環境では見分けがつかなくなる。
